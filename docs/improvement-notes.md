# 개선 노트

배포 후 직접 눌러 보며 찾은 문제와, 무엇을 왜 바꿨는지 기록합니다.

## 1. 상품 데이터를 한 곳으로 합침

**문제**
- 목록용 데이터(`lib/deals.ts`, 12개)와 상세용 데이터(`app/api/deals/[id]/route.ts`, 2개)가 따로 있었다.
- 3~12번 상품 상세에 들어가면 API가 404를 돌려줬고, 화면은 그 응답을 상품 데이터로 착각해 `images.map`에서 오류가 났다.
- 같은 1번 상품인데 목록과 상세의 마감 시간이 달랐다. (목록 07:31 남음, 상세 01:29 남음)

**원인**
- 같은 상품을 두 파일에 손으로 따로 적었다.
- SWR fetcher가 응답 상태(`res.ok`)를 확인하지 않았다.

**해결**
- 상세 전용 정보(이미지, 옵션, 반품 정책 등)를 id 기준으로 `lib/deals.ts`에 두고, `getDealById()`에서 기본 정보와 합쳐 반환한다. 같은 값을 두 번 적지 않는다.
- 상세 API는 `getDealById()`만 호출하고, 없으면 404를 반환한다.
- fetcher가 실패 응답이면 에러를 던지고, 화면은 404일 때 "상품을 찾을 수 없어요" 안내를 보여준다.

**이렇게 한 이유**
- 실제 서비스에서는 상품 테이블이 하나이고, 목록과 상세는 같은 테이블에서 필요한 칸만 다르게 꺼낸다.
- 데이터 접근을 `lib/deals.ts`로 모아 두면, Supabase로 바꿀 때 이 파일 안쪽만 바꾸면 되고 화면·API 코드는 그대로 둘 수 있다.

## 2. 카테고리 탭이 실제로 목록을 거르게 함

**문제**
- 탭을 눌러도 URL의 `?category=`만 바뀌고 목록은 그대로였다.
- 탭 id(`food`)와 상품 데이터 값(`식품`)이 서로 달라 연결할 기준도 없었다.

**해결**
- `lib/categories.ts`에 탭 id ↔ 상품 category 값 매핑을 한 곳에 정의했다.
- `getAllDeals`, `getDealsByTab`, `/api/deals`가 category를 받아 거른다.
- `/best`, `/today`는 서버 컴포넌트에서 `searchParams`를 읽어 반영한다.
- 오늘의 딜에서 탭·페이지를 옮겨도 카테고리가 유지되게 링크를 만든다.
- 목록이 아닌 페이지(상세 등)에서 탭을 누르면 `/best`로 이동하고, 카테고리를 바꾸면 1페이지로 돌아간다.

**이렇게 한 이유**
- 필터 상태를 URL에 두면 새로고침·뒤로가기·링크 공유에도 같은 화면이 나온다.
- 서버 컴포넌트에서 URL을 읽어 필터링하므로, 클라이언트 상태 관리 없이 처음 그려질 때부터 거른 결과가 나온다.

## 3. 반응형 레이아웃

**문제**
- 좌우 여백 120px, 4열 그리드, 상세 50:50 분할이 고정값이라 390px 화면에서 카드가 실처럼 얇아지고 메뉴 글자가 세로로 쪼개졌다.

**해결**
- 여백은 16px(모바일) → 32px(md) → 120px(lg)로 늘린다.
- 카드 그리드는 2열 → 3열(md) → 4열(lg)로 바뀐다. 스켈레톤도 같은 규칙을 쓴다.
- 헤더는 모바일에서 검색창을 아래 줄 전체 너비로 내리고, 카테고리 탭은 가로 스크롤로 바꿨다.
- 상세는 모바일에서 이미지 위·정보 아래로 쌓고, 메인 이미지는 정사각 비율을 준다.

**이렇게 한 이유**
- 커머스는 모바일 비중이 가장 크다. Tailwind의 모바일 우선 방식에 맞춰 기본값을 모바일로 두고 큰 화면에서 늘린다.

## 다음에 고칠 것
- 상세 페이지를 서버 컴포넌트로 전환하고 `loading.tsx`, `not-found.tsx`, `generateMetadata` 추가
- 마감 시간 계산 버그: `today`를 파일이 처음 불러와질 때 한 번만 계산하고, 서버(UTC)와 한국 시간 차이를 고려하지 않음
- 목록 썸네일의 흑백 필터와 쓰이지 않는 덮개 요소 제거
- 일부 상품 사진이 상품명과 맞지 않음 (예: 이어폰에 선글라스 사진)
- 이미지 캐러셀의 화살표와 실제 슬라이드 위치 동기화
- 홈 화면, 검색, 접근성(aria-label), 색상 토큰 정리, 테스트
